## Why these choices

Chọn "giữ hành vi hiện tại" cho đa số quyết định vì code đang chạy đã khớp các spec đã Approved của
Submission và Learning, tránh phải sửa contract giữa chừng. D-02/D-04 không hỏi lại vì SUB-001,
SUB-002-FR-019 và SUB-003-FR-011 đã chốt; việc lọc output là quyền xem phía Submission nên Judge
vẫn gửi dữ liệu thô. Quy tắc lỗi theo vùng code được chọn thay vì chỉ exit code vì JDG-003-FR-007/
JDG-004-FR-006 cấm chỉ dựa vào exit code. Trần sandbox giữ nguyên nhưng hai hành vi nguy hiểm của
code (workspace `0777`, map 137 → MLE) được ghi thành deviation phải sửa thay vì hợp pháp hoá.

## How the feature works

Chưa triển khai tính năng. Theo spec đã duyệt: Submission phát `judge.request` → Judge xác thực
payload (thiếu định danh thì log + ACK + bỏ) → tạo workspace riêng, ghép `sourceCode` + harness
( FUNCTION/OOP ) → compile một lần với trần `max(3×TL, 10s)` → chạy từng testcase, mỗi testcase một
process/container trong sandbox có trần D-11 → so output bằng CRLF→LF + `trimEnd()`, sai là dừng ngay
→ trả `JudgeResult` với điểm/runtime đã tính, publish và chỉ ACK sau publisher confirm → Submission
lưu kết quả (kể cả stdout/stderr thô), chỉ hiện output của Run theo SUB-003.
